# ADR-0001：采用“中途接入”而非“从头回放”

- 状态：已接受
- 日期：2026-11-19
- 决策者：项目发起人、设计讨论

## 背景

最初的设计是“严格对齐”：回放从素材第 0 秒开始，与目标客户端的“开始跑步”时刻对齐。讨论中发现两个问题：

1. 目标客户端的 t0 定义不明确（点击、倒计时、首定位、配置加载），人工对齐误差 1–3 秒；
2. 用户的实际使用方式是“先开助手、后开客户端”，客户端本来就会在运动中途启动。

## 决策

采用**中途接入**：回放持续播放素材，目标客户端在任意时刻加入，从当前素材位置开始消费数据。

## 后果

正面：

- 不需要精确对齐 t0；
- 与“运动中途打开客户端”的真实行为一致；
- 接入点随机，起点位置每次不同，反而更自然。

负面：

- 剩余里程受接入延迟影响，素材要留余量；
- 每次会话的起点不同，验收记录要记录接入偏移；
- 时基与计步基线仍需重建，不能复制旧时间戳。

## 备选方案

- 严格对齐：误差不可控，放弃；
- 协议层伪造：需要破解签名，且不符合“在客户端内完成”的目标，放弃。
