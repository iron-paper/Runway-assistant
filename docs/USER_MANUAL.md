## 1. 产品概述

### 1.1 这是什么

跑道助手是一款**运动数据记录与复盘工具**。它把一次真实跑步的多源数据完整记录下来，形成可校验、可回放的“素材”；之后在需要时，把素材按原始时间轴重新提供给系统，让运动类客户端看到同一次跑步的数据。

它的设计目标有三个：

1. **完整**：记录的不只是位置，还包括 IMU、计步、活动识别、气压、设备状态；
2. **自洽**：素材内部满足速度、步频、步幅、海拔之间的物理关系；
3. **可控**：回放是“中途接入”，接入点、结束点、复位都由使用者控制。

### 1.2 这不是什么

- 不是“一键代跑”按钮：它要求你先真实跑一次，并把数据录下来；
- 不是跨设备工具：素材与设备、系统版本绑定，换机需重新标定；
- 不是无人值守系统：接入点选择、开始、结束、复位都需要人工确认。

### 1.3 适用场景

- 运动数据研究：分析一次跑步的传感器特征；
- 轨迹复盘：把真实跑步数据在客户端里重现，检查记录一致性；
- 客户端兼容性测试：验证客户端对同一份数据的处理逻辑。

## 2. 工作原理

### 2.1 两段式结构

```
第一次：真实跑步 ──► 录制 ──► 素材（JSONL + 清单）
之后：  素材 ──► 回放 ──► 注入系统 ──► 客户端看到同一次跑步
```

录制端只读系统数据，不做任何写入；回放端通过独立注入层把素材送回系统。两段之间通过素材文件解耦，可以分别升级。

### 2.2 中途接入模型

回放不是“从头开始演一遍”，而是让客户端从素材的**某一秒**开始消费数据：

```
素材时间轴:  0 ───── join ──────────────── end
客户端看到:              └── 从这里开始 ──┘
```

这样做的原因：目标客户端允许在“已经在运动”的状态下开始记录，所以接入点可以落在素材中间。代价是**剩余里程**必须覆盖目标里程，接入延迟要控制。

### 2.3 时间轴重建

回放时不复制录制时的绝对时间戳，而是以本次会话为原点，按素材相对偏移重建时间戳，写入当前开机时基。这样客户端看到的时间永远是“现在”，不会出现时间倒流。

## 3. 环境与前提

使用前请逐项确认：

| 编号 | 前提 | 说明 |
|---|---|---|
| P1 | 设备已 root | 特权注入层需要 |
| P2 | 目标客户端版本锁定 7.3.80 | 关闭自动更新，升级需整体重新验收 |
| P3 | 目标客户端允许“移动中开始” | 本产品的中途接入依赖此行为 |
| P4 | 注入层覆盖位置、IMU、计步、活动识别 | 仅改定位会导致步频为 0 |
| P5 | 开阔场地（操场） | 降低网络定位对轨迹的拉扯 |
| P6 | 单素材策略 | 一份录制、有限次数回放 |

任一项不满足，请先在测试环境验证，再进入正式流程。

## 6. 录制流程

### 6.1 录制前

- 电量 ≥ 50%，存储 ≥ 2GB；
- 关闭目标客户端，避免录制期间产生成绩；
- 确认 WiFi 状态与正式回放时一致；
- 站在预定起点。

### 6.2 录制步骤

1. 打开跑道助手 → 录制页 → 点“开始记录”；
2. **静止 60 秒**：让定位从无到有、精度收敛，这段是回放的“前奏”；
3. 点“标记跑步开始”，按预定路线跑；
4. 跑够目标距离后，继续跑到**整圈点**（400m 跑道按整圈结束）；
5. 点“标记跑步结束”，原地静止 30 秒；
6. 点“停止记录”，等待写入完成。

### 6.3 录制约束

| 项 | 建议值 |
|---|---|
| 总长度 | ≥ 3.2km，推荐 5km |
| 前奏 | 60 秒 |
| 结束段 | 30 秒 |
| 采样 | 位置 1Hz、IMU 50–100Hz、计步事件、活动识别、气压 |
| 设备 | 固定一台，固定 ROM 与系统版本 |
| 场地 | 与回放同一操场、同一时段窗口 |

### 6.4 校验

录制完成后自动运行校验，也可手动执行：

```bash
python tools/validate_recording.py <素材目录>
```

校验项包括时间单调、速度区间、步频区间、配速区间、步数一致、字段完整、轨迹闭合（可选）。任一项失败，素材标记为“不可用”。

## 7. 回放流程

### 7.1 固定顺序（不得调换）

```
① 打开跑道助手 → 回放页 → 选择素材 → 校验通过
② 点“注入就绪”（目标客户端尚未启动）
③ 打开目标客户端 → 登录 → 进入跑步页
④ 点目标客户端“开始跑步”，同时点跑道助手“开始回放”
⑤ 正片 1:1 播放，保持前台亮屏
⑥ 达到目标里程：先点“暂停”，再点目标客户端“结束”
⑦ 目标客户端结算完成后，点“停止并复位”
```

### 7.2 接入偏移

- 默认从素材的“跑步开始”标记处接入；
- 也可手动选择偏移，但必须满足：**剩余里程 ≥ 目标里程 + 余量**；
- 接入延迟从“注入就绪”开始计时，上限 5 分钟，超时请复位重来。

### 7.3 结束与复位

- 结束前先暂停注入，避免结算期间位置继续变化；
- 结束后注入器停在最后位置，不继续播放；
- 每次会话结束必须复位，否则下一次会话的剩余里程不足；
- 复位后确认手机真实定位已恢复。

### 7.4 使用节奏

| 项 | 建议 |
|---|---|
| 单素材使用次数 | ≤ 3 次 |
| 单日会话 | ≤ 1 次 |
| 每周会话 | 3–5 次 |
| 时段 | 固定窗口，贴合正常作息 |

## 8. 内置标准（“关于 → 数据说明”展示）

跑道助手在“关于”页以正文形式展示以下内容，供使用者随时查阅：

1. **数据来源**：本工具记录设备的位置、运动传感器、计步、活动识别、气压与设备状态，仅用于本地回放与复盘。
2. **素材限制**：单份素材建议使用不超过 3 次；超过后轨迹与步频会呈现重复特征，应重新录制。
3. **接入限制**：从“注入就绪”到“开始回放”不超过 5 分钟；剩余里程必须覆盖目标里程。
4. **结束约定**：结束前先暂停注入；结束后复位，避免下一次会话里程不足。
5. **停止条件**：连续 2 次出现“数据异常/成绩无效”，停止使用并回滚到上一个通过验收的配置。
6. **版本约定**：适配版本固定后，客户端升级需重新验收。
7. **适用范围**：本工具用于个人学习、运动数据研究与兼容性测试，使用者自行确认使用场景。

## 9. 数据说明与隐私

- 素材保存在应用私有目录，默认加密，密钥由系统 Keystore 管理；
- 导出素材需二次确认；
- 会话记录只保留统计字段（里程、配速、步频、结论），默认不保留原始轨迹明文；
- 日志默认不含坐标，调试模式需手动开启。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 步频显示 0 | 注入层未覆盖 IMU/计步 | 检查注入层状态，重新验收 |
| 位置被拉回起点 | 网络定位权重高 | 换开阔地、关 WiFi 扫描后重试 |
| 时间戳异常/倒退 | 回放复制了旧时间戳 | 检查时基重建逻辑 |
| 开始被拦截（请静止/请走起点） | 客户端版本行为变化 | 复核 K1 条件，确认版本 |
| 结束提示“未在终点范围” | 结束点不在整圈点 | 按整圈结束，或改用自由模式 |
| 里程不足 | 接入延迟过长 | 复位，缩短接入时间 |
| 注入中途断开 | 权限/保活被系统限制 | 关闭省电限制，重试一次 |
| 成绩无效 | 数据一致性不足 | 查看校验报告，重新录制 |

## 11. 常见问题（FAQ）

**Q1：为什么一定要先真实跑一次？**
素材来自真实跑步，才能保证传感器之间的物理关系自洽；合成数据很难同时满足速度、步频、步幅、海拔的约束。

**Q2：可以录 3 公里吗？**
可以，但建议 5 公里。中途接入会消耗一部分素材，3 公里素材的剩余里程容易不足。

**Q3：为什么结束要按整圈？**
若客户端有“回到终点”的判定，整圈结束能保证结束点与接入点在空间上重合。自由模式无此约束。

**Q4：同一份素材能一直用吗？**
不建议。单份素材使用超过 3 次，轨迹与步频的重复特征会变得明显。

**Q5：换手机还能用吗？**
素材与设备、系统版本绑定。换机后需要重新录制与标定。

**Q6：客户端升级了怎么办？**
先回滚到已验证版本；确需升级时，按验收标准重新跑一遍 M3。

**Q7：为什么回放时人要站在操场？**
让真实网络定位与素材起点重合，减少起步阶段的定位拉扯；同时让现场观察与数据一致。

**Q8：回放时手机需要联网吗？**
需要。客户端要登录、拉取配置、上传成绩；注入层只影响传感器与定位。

## 12. 已知限制

1. 接入点随机，每次会话的起点不同；
2. 单素材重复使用会形成跨场次指纹；
3. 注入层依赖设备与系统版本；
4. 客户端行为可能随版本变化，K1 需重新验证；
5. 长时间回放对电量与散热有要求。
