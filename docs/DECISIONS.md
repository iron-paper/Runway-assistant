# 关键决策记录

本文档存档项目启动前与设计阶段确认的结论，作为后续实现的依据。编号与对话中的编号一致。

## 一、否决项（K1–K5）

| 编号 | 问题 | 结论 | 影响 |
|---|---|---|---|
| K1 | 目标客户端是否允许“移动中开始” | 允许 | 采用中途接入架构，不要求 t0 与素材起点对齐 |
| K2 | root 能否通过环境检测 | 通过 | 可走特权注入层，不走 Mock Provider |
| K3 | 注入层能否覆盖传感器全链路 | 可以 | 位置、IMU、计步、活动识别统一注入 |
| K4 | 高德网络定位是否拉回轨迹 | 不会（操场条件下） | 站在录制起点即可，无需额外网络干预 |
| K5 | 目标版本能否锁定 | 锁定 7.3.80 | 素材与标定可复用，升级需重新验收 |

## 二、标准（S1–S10）

| 编号 | 标准 | 结论 |
|---|---|---|
| S1 | 验收标准 | 单素材策略下调整为：连续 2–3 次通过 + 14 天无复核驳回 |
| S2 | 数据规范 | 双时间域；坐标系统一 WGS-84 落盘，按注入层输出 |
| S3 | 录制规范 | 单份素材，建议 5km；前奏 60s；结束段 30s |
| S4 | 会话规范 | 助手先启动；接入延迟 ≤5 分钟；结束先暂停；每会话复位 |
| S5 | 素材管理 | 单素材为主，使用次数 ≤3，超限补录（替代原轮换方案） |
| S6 | 设备与版本冻结 | 固定设备、ROM、7.3.80；变更即重新基线 |
| S7 | 账号与网络 | 一机一号；固定网络；贴合正常作息 |
| S8 | 隐蔽性 | 包名/名称中性；无调试日志落盘；素材加密 |
| S9 | 失败与回滚 | 连续 2 次异常即停，回滚上一通过配置 |
| S10 | 变更管理 | 变更分四级，逐级回归 |

## 三、设计阶段确认的技术结论

| 主题 | 结论 |
|---|---|
| 测量模块 | 目标客户端以 GPS 为主、计步/步态为辅，无真正惯导 |
| 签到机制 | 点位签到 + 人脸抽检 + 课堂考勤 + 扫码，四类并存 |
| 接入模型 | 客户端从素材某一秒开始消费，接入点随机 |
| t0 对齐 | 不需要与素材起点严格对齐，但需“开始回放”与“开始跑步”同步 |
| TTFF | 通过前奏（静止收敛）消除“瞬间出点”的不自然 |
| 时基 | 回放时间戳必须按本次开机时基重建 |
| 基线 | 计步累计值必须 rebase 到本次开机真实值 |
| 剩余里程 | 素材长度 ≥ 目标里程 + 接入延迟余量 |
| 传感器一致性 | 位置、IMU、计步、活动识别必须同时替换 |
| 跨场次指纹 | 单素材使用次数是主要风险控制手段 |
| root 隐蔽 | 注入层越深越干净；Magisk 模块 < 内核模块 < 自定义 ROM |
| 网络定位 | 操场可降低权重，但不能完全消除；需实测确认 |
| 版本演进 | 锁定版本；升级前重新标定 |

## 四、不在本项目范围内

- 目标客户端的协议逆向与请求伪造；
- 人脸核验相关能力；
- 服务端规则的猜测与对抗；
- 多设备、多账号的批量运营。
